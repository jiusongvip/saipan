# ADR-002：集团表单 API 契约

- 状态：**BLOCKED（契约未确认，禁止实现提交逻辑）**
- 日期：2026-10-13
- 决策方：集团 API 负责人 + 项目负责人（均未确认）
- 依据：开发文档 2.1（复用集团 `POST /api/contact`，禁止前端直连飞书或暴露密钥）、6.1/6.2（表单字段与安全）、6.3（成功与失败体验）、6.5（只读汇总端点）、8.1 第 12/13 项、9/P0 第 4 项、13.2（API 责任边界）、13.4（数据保留与删除 SLA）
- 关联事实：`fact-register.csv` 的 `api-contact-contract`、`legal-privacy-retention`、`analytics-consent-policy`、`channel-staffing-rota`

## 为什么是 BLOCKED

文档只说明"复用集团既有 `POST /api/contact`，目标为飞书多维表格"，但**没有给出完整接口契约**。在字段名、类型、枚举、鉴权、响应结构、限流、幂等与数据保留责任确认之前，任何实现都是猜测接口，违反文档 0.1 第 4 条与 2.1 末段（"先确认后实现，不可猜测接口"）。

因此本阶段：**不写提交代码、不定义伪字段、不建 mock 端点**。`docs/forms/form-spec.md` 与前端表单实现须待本 ADR 转为 accepted 后再落地。

## 契约未确认前的前端降级策略

1. **不猜测接口**：不实现 `fetch` 提交、不硬编码字段名、不写占位 endpoint 或假数据返回。
2. 表单渲染为"暂不可提交"状态：
   - 保留可见字段与隐私勾选的静态展示，用于内容评审与线框验收；
   - 提交按钮禁用并显示"提交通道尚未开通，请使用以下已确认联络方式"；
   - 未确认前该提示不得指向任何未经登记的账号。
3. **仅展示已确认的联络渠道**：渠道一律读取 `data/contact-channels.json`，且只有 `enabled=true` 且对应事实条目（`channel-*` = obtained:yes / publishable:true）的渠道才渲染；当前状态下所有渠道条目均未取得，因此页面呈现"联络方式待院方确认"的空状态（不是编造账号）。
4. `contact_success` 页在契约确认前保持 `status=blocked`，`noindex=true`，不进入 sitemap，也不作为表单跳转目标。
5. 事件埋点降级：只允许 `cta_click`、`messaging_entry_click`；`form_start`/`form_submit_success`/`form_submit_error` 在提交能力开通后才启用，不得用假事件填充报表。
6. 失败体验（文档 6.3）在实现阶段须覆盖：API 失败、网络失败、重复提交三种用例，并进入 `tests/` 契约测试。
7. 文档 12 的上线前检查项"每种语言有可用且有人值守的联系渠道"在契约与渠道双未确认前保持未勾选状态。

## 解除阻塞的条件

- A–H 全部条目回填并由集团 API 负责人与法律顾问书面确认；
- 字段白名单与 `docs/forms/form-spec.md` 一致（同一 PR 内更新）；
- 密钥归属与代理层实现方式确定，确认前端不接触密钥；
- 数据保留/删除 SLA 与隐私声明文本一致；
- 至少一组真实请求/响应样例可用于契约测试。
